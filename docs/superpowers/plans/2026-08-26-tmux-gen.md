# tmux-gen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `prefix + g` opens a tmux popup that takes a natural-language request and either answers it or generates a shell command, inserted into the pane without a newline — never executed.

**Architecture:** One bash script, `bin/tmux-gen`, run inside `display-popup -E` and passed the originating `#{pane_id}`. Four functions with clear boundaries — `gather_context`, `query`, `parse_reply`, `render_and_act` — plus a `main` that is skipped when the script is sourced as a library, so the pure functions can be unit-tested without a popup or an API call. A sibling `bin/tmux-gen-selftest` drives them against stub fixtures.

**Tech Stack:** bash, `jq` (already a dependency of the deletion circuit breaker), `claude -p` with Sonnet and tools disabled, tmux 3.5a `display-popup` / `send-keys -l` / `set-buffer -w`.

**Spec:** `docs/superpowers/specs/2026-08-26-tmux-gen-design.md`
**Branch:** `tmux-gen` (cut from `tmarchy`, which is live and unmerged — do NOT check out master)

---

## Facts this plan relies on

Measured during design. Do not re-litigate:

1. `claude -p` **without** a system prompt takes 20–41s and misreads requests as instructions to run commands. **With** the system prompt below: 5–6.5s and a clean single line. The system prompt is load-bearing.
2. `--disallowed-tools Read Bash Glob Grep WebFetch WebSearch Edit Write Task NotebookEdit TodoWrite` genuinely disables filesystem access — verified by asking the model to read a file and having it report it cannot.
3. `--allowed-tools ""` does **not** work: the empty string is swallowed and `claude` then reports "Input must be provided". Use `--disallowed-tools` with an explicit list.
4. The prompt must arrive on **stdin**, not as a positional argument, when combined with these flags.
5. `jq` is installed and already used by `.claude/hooks/deletion-circuit-breaker.sh`.

## File structure

```
bin/tmux-gen            the tool: context, query, parse, render, insert
bin/tmux-gen-selftest   fixture-driven tests, no network, no real Claude
.tmux.conf              one bind line
```

Both scripts live in `bin/` alongside `tmux-askpass` and the `tmux-sidebar-*` family, matching the existing convention. `bin/` is on the tmux server's PATH (see the guarded PATH line in `.tmux.conf`), but the binding uses an absolute path anyway — the sidebar hooks broke on exactly that assumption when a server restarted with a different environment.

```bash
#!/usr/bin/env bash
# tmux-gen — ask Claude for a shell command, insert it WITHOUT running it.
#
# Bound to prefix + g via display-popup. Deliberately toolless: the query has
# no filesystem access, so a wrong answer costs a wasted popup, not a deleted
# directory. Nothing here ever appends a newline to send-keys — the governing
# rule is that this tool may put text on your prompt line and nothing else.
#
# Sourced with TMUX_GEN_LIB=1 it defines its functions and exits, so
# bin/tmux-gen-selftest can test the pure parts without a popup or an API call.
set -uo pipefail

CLAUDE_BIN="${TMUX_GEN_CLAUDE:-$HOME/.local/bin/claude}"
TIMEOUT="${TMUX_GEN_TIMEOUT:-30}"
MODEL="${TMUX_GEN_MODEL:-sonnet}"

# Measured, not guessed: without this prompt claude -p took 20-41s and answered
# as an agent that cannot run things ("Bash is disabled, so I can't run git
# status"). With it: 5-6.5s and one clean line. Treat it as load-bearing.
SYSTEM_PROMPT='You generate shell commands and short terminal answers. You have no tools and are not expected to run anything.

Reply with ONE JSON object and nothing else:
  {"kind":"command","command":"<a single shell command>","note":"<short why, max 12 words>"}
  {"kind":"answer","note":"<answer, max 3 short lines>"}

Use "command" when the user wants something done in a shell. Use "answer" when they want an explanation.
Never wrap the JSON in markdown fences. The command must be a single line, safe to paste at a prompt.'

gather_context() { :; }
query() { :; }
parse_reply() { :; }
render_and_act() { :; }
# TMUX_GEN_MAIN_RAN is a sentinel for the selftest: it is the only observable
# proof that the library-mode guard below actually skipped main. Keep it as
# main's first statement when the real body lands in Task 5.
main() { TMUX_GEN_MAIN_RAN=1; :; }

[ "${TMUX_GEN_LIB:-}" = "1" ] || main "$@"
```

- [ ] **Step 3: Implement parse_reply**

Replace `parse_reply() { :; }` in `bin/tmux-gen` with:

```bash
# Sets REPLY_KIND (command|answer), REPLY_CMD, REPLY_NOTE.
#
# Every path that cannot positively identify a command falls through to
# "answer", because render_and_act only offers Enter for a command. Garbage in
# must never produce something insertable.
parse_reply() {
    local raw="${1:-}" json
    REPLY_KIND=""; REPLY_CMD=""; REPLY_NOTE=""

    # Strip markdown fences the model was told not to use but sometimes does.
    json=$(printf '%s' "$raw" | sed -e 's/^[[:space:]]*```[a-z]*[[:space:]]*//' -e 's/```[[:space:]]*$//')
    # Take the first {...} block, so a prose preamble does not break the parse.
    json=$(printf '%s' "$json" | sed -n '/{/,/}/p')

    if [ -n "$json" ] && printf '%s' "$json" | jq -e . >/dev/null 2>&1; then
        REPLY_KIND=$(printf '%s' "$json" | jq -r '.kind // ""')
        REPLY_CMD=$(printf '%s' "$json" | jq -r '.command // ""')
        REPLY_NOTE=$(printf '%s' "$json" | jq -r '.note // ""')
    fi

    # A newline inside the command is NOT insertable. send-keys -l sends a
    # literal newline byte, and a terminal in canonical mode submits the line on
    # any newline byte — not just the Enter key — so an embedded one executes
    # without the user pressing anything. "We never append Enter" is a promise
    # about the call site; this closes the payload side of it.
    case "$REPLY_CMD" in
        *$'\n'*) REPLY_KIND="answer" ;;
    esac

    if [ "$REPLY_KIND" != "command" ] || [ -z "$REPLY_CMD" ]; then
        REPLY_KIND="answer"
        REPLY_CMD=""
        [ -n "$REPLY_NOTE" ] || REPLY_NOTE="$raw"
    fi
}
```

```bash
# Split in two so the directory logic is testable without a live tmux pane.
# gather_context resolves the pane; gather_context_from_dir does the rest.
gather_context_from_dir() {
    CTX_CWD="${1:-$PWD}"
    CTX_BRANCH=$(git -C "$CTX_CWD" rev-parse --abbrev-ref HEAD 2>/dev/null) || CTX_BRANCH=""
    # A detached HEAD reports the literal string "HEAD", which tells the model
    # nothing; a short sha at least identifies the commit.
    if [ "$CTX_BRANCH" = "HEAD" ]; then
        CTX_BRANCH=$(git -C "$CTX_CWD" rev-parse --short HEAD 2>/dev/null) || CTX_BRANCH=""
    fi
}

gather_context() {
    local pane="${1:-}" cwd=""
    [ -n "$pane" ] && cwd=$(tmux display-message -p -t "$pane" '#{pane_current_path}' 2>/dev/null)
    gather_context_from_dir "${cwd:-$PWD}"
}
```

```bash
# flags, passing it positionally makes claude report "Input must be provided".
query() {
    local question="${1:-}" ctx

    [ -n "$CTX_BRANCH" ] && ctx="$ctx
branch: $CTX_BRANCH"

        -p --model "$MODEL" \
```

```bash
# Draws the result and waits for one key. Enter is offered ONLY for a command;
# an answer gets no insert path at all, which is what makes an unparseable
# reply harmless.
render_and_act() {
    local pane="${1:-}"
    printf '\n'
    if [ "$REPLY_KIND" = "command" ]; then
        printf '  %s\n' "$REPLY_CMD"
        [ -n "$REPLY_NOTE" ] && printf '  %s\n' "$REPLY_NOTE"
        printf '\n  [Enter] insert   [y] copy   [q] close  '
        local key
        IFS= read -r -n1 -s key
        case "$key" in
            "")
                # -l is mandatory: without it tmux reads tokens as key NAMES, so
                # a command containing Enter, Space or ';' becomes keystrokes.
                # No newline is ever sent: inserting is not running.
                #
                # The newline check is deliberate belt-and-braces. parse_reply
                # already degrades a multi-line command to an answer, so this
                # should be unreachable — but it is the last line of defence for
                # the one property the tool exists to provide, and a future edit
                # to the gate must not be able to silently open it.
                case "$REPLY_CMD" in
                    *$'\n'*) : ;;
                    *) tmux send-keys -t "$pane" -l "$REPLY_CMD" ;;
                esac
                ;;
            y|Y)
                # load-buffer -w, not set-buffer: reading from stdin avoids any
                # argument-quoting question for arbitrary command text, and -w
                # routes through OSC 52 to the host clipboard — the same path
                # @override_copy_command already uses, so this works in ShellFish.
                printf '%s' "$REPLY_CMD" | tmux load-buffer -w -
                ;;
        esac
    else
        printf '  %s\n' "$REPLY_NOTE"
        printf '\n  [q] close  '
        IFS= read -r -n1 -s _
    fi
    printf '\n'
}
```

```bash
main() {
    # Sentinel for the selftest's library-mode assertion — see Task 1. Without
    # it, "sourcing does not run main" has nothing observable to check and
    # passes even when the guard is broken.
    TMUX_GEN_MAIN_RAN=1
    local pane="${1:-}" question
    gather_context "$pane"

    printf 'ask (%s%s)\n' "${CTX_CWD##*/}" "${CTX_BRANCH:+ @$CTX_BRANCH}"
    IFS= read -r -e -p '> ' question || exit 0
    [ -n "${question// /}" ] || exit 0

    printf '\n  thinking...\r'
    local raw
    raw=$(query "$question")
    local rc=$?

    if [ $rc -ne 0 ] && [ -z "$raw" ]; then
        printf '  query failed (exit %s)\n\n  [q] close  ' "$rc"
        IFS= read -r -n1 -s _
        exit 1
    fi

    parse_reply "$raw"
    render_and_act "$pane"
}
```

```bash
echo "safety: insert must not execute"

# A throwaway server needs BOTH -L and -f /dev/null. Without the latter it
# sources the real ~/.tmux.conf, drags in tpm, and leaks an orphaned
# tmux-autoreload watcher when the server dies.
SOCK="tmux-gen-test-$$"
CANARY="/tmp/tmux-gen-canary-$$"
SAFE_STUB=$(mktemp -d)

cleanup_safety() {
    tmux -L "$SOCK" kill-server 2>/dev/null
    rm -f "${TMUX_TMPDIR:-/tmp}/tmux-$(id -u)/$SOCK" "$CANARY"
    rm -rf "$SAFE_STUB"
}
trap cleanup_safety EXIT

cat > "$SAFE_STUB/claude" <<STUB
#!/usr/bin/env bash
cat > /dev/null
printf '%s' '{"kind":"command","command":"rm -rf $CANARY","note":"destructive on purpose"}'
STUB
chmod +x "$SAFE_STUB/claude"

: > "$CANARY"
tmux -L "$SOCK" -f /dev/null new-session -d -x 120 -y 24
PANE=$(tmux -L "$SOCK" display-message -p '#{pane_id}')

# Drive the tool from INSIDE the throwaway server.
#
# This matters more than it looks: tmux-gen calls plain `tmux send-keys`, which
# resolves through $TMUX (or the default socket) — NOT through any -L we used to
# create the server. Running it with $TMUX unset or empty would send the
# generated command to the USER'S LIVE SERVER. Empty is not isolation; tmux
# falls back to the default socket. So run it as a command inside the test
# server, where $TMUX is correct by construction.
tmux -L "$SOCK" set-environment -g TMUX_GEN_CLAUDE "$SAFE_STUB/claude"
tmux -L "$SOCK" respawn-pane -k -t "$PANE" \
  "printf 'delete the canary\\n' | bash '$DIR/tmux-gen' '$PANE'; sleep 5"
sleep 3
tmux -L "$SOCK" send-keys -t "$PANE" Enter   # the [Enter] insert choice
sleep 2

[ -f "$CANARY" ] \
  && pass "canary survived: the command was inserted, not executed" \
  || fail "canary survived: the command was inserted, not executed" "canary exists" "canary was DELETED"

tmux -L "$SOCK" capture-pane -p -t "$PANE" 2>/dev/null | grep -q -- "rm -rf $CANARY" \

cleanup_safety
trap - EXIT
```
